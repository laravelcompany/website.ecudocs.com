# Brand Content Generation & Validation Pipeline (Phase 2)

AI-assisted enrichment of the brand content used by EcuDocs.com.

```
Existing Brand JSON  →  DeepSeek  →  Structured Brand Content
                                     → Schema Validation → Quality Validation
                                     → Brands.generated.json → (review) → Promote
```

Safety rule: the pipeline must never enter fabricated automotive/ECU technical
facts into production. Unknown facts must be omitted, not guessed.

## Files

| File | Purpose |
|------|---------|
| `scripts/generate-brands.mjs` | Generates/enriches brand content. Writes candidates to `brands.generated.json`. |
| `scripts/promote-brands.mjs` | Validates `brands.generated.json` and, with `--apply`, writes accepted records into `src/data/<slug>/brand.json`. Also the `validate:generated` command (validation/preview only). |
| `scripts/lib/ai.mjs` | DeepSeek client, structured prompt builder, tolerant JSON parser, mock provider. |
| `scripts/lib/quality.mjs` | Quality checks (placeholders, malformed model names, duplicate FAQs, empty strings, suspicious claims, etc.). |
| `src/lib/brand-schema.js` | Phase 1 Zod schema (`parseBrand`, `slugify`). Reused unchanged. |
| `brands.generated.json` | Git-ignored output of the generation step (never committed). |
| `brands.generation.log.jsonl` | Git-ignored per-brand JSONL log (never committed). |

## Required environment variables

Copy `.env.example` to `.env` and fill in:

| Variable | Required | Description |
|----------|----------|-------------|
| `DEEPSEEK_API_KEY` | Yes for real generation | DeepSeek API key. If unset, the pipeline falls back to the **mock provider** (synthetic, non-promotable test data). |
| `DEEPSEEK_BASE_URL` | No | Default `https://api.deepseek.com`. |
| `DEEPSEEK_MODEL` | No | Default `deepseek-chat`. |
| `DEEPSEEK_TEMPERATURE` | No | Default `0.2` (low = more factual). |
| `DEEPSEEK_MAX_TOKENS` | No | Default `4000`. |

No API secrets are ever written to logs or output files.

## Generation command

```bash
npm run generate:brands                # process all brands with brand.json
npm run generate:brands -- --limit 3   # first N brands in slug order
npm run generate:brands -- --limit 10
npm run generate:brands -- --brand ac --brand ford
npm run generate:brands -- --brand ac,ford
```

Options:

| Option | Description | Default |
|--------|-------------|---------|
| `--limit <n>` | Process at most `n` brands | all |
| `--brand <slug>` | Only the given brand (repeatable / comma-separated) | all |
| `--provider <deepseek\|mock>` | Force a provider. Default: `deepseek` if `DEEPSEEK_API_KEY` is set, otherwise `mock` (with a warning). | auto |
| `--retries <n>` | Retry attempts per brand for failed AI requests | 2 |
| `--force` | Also regenerate fields that already exist (default: only missing) | off |
| `--out <file>` | Generated-record output file | `brands.generated.json` |
| `--log <file>` | JSONL log file | `brands.generation.log.jsonl` |
| `--dry-run` | List intended work, call nothing, write nothing | off |
| `--help` | Usage | - |

Every run replaces the previous `brands.generated.json`. Re-running with a
higher `--limit` regenerates candidates for all selected brands whose
enrichable fields are still missing (completed brands are skipped).

## What is enriched, what is preserved

- **Never generated by AI:** `name`, `slug`, `description`, `logo`,
  `productionModels`, `discontinuedModels` (existing verified identity).
- **Enrichable when missing:** `history`, `country`, `founded`,
  `parent_company`, `current_status`, `vehicle_types`, `popular_models`,
  `ecu_information`, `common_ecu_manufacturers`, `related_brands`,
  `seo_title`, `seo_description`, `faq`.
- **Strict merge:** an existing value is never replaced unless `--force` is
  passed. `popular_models` may be seeded from the brand's `models.json`.

## Validation command

```bash
npm run validate:brands       # Phase 1: schema-validate all src/data/<brand>/brand.json (43/43)
npm run validate:generated    # validate the records in brands.generated.json (preview what would be applied)
```

Validation stages in the pipeline:

1. **JSON syntax** — tolerant parser (handles code fences, trailing prose).
2. **Schema** — Zod `brandSchema` from Phase 1.
3. **Field guard** — rejects AI attempts to emit `name`/`slug`/`description`/`logo`/counts.
4. **Quality checks** — placeholders, empty strings, malformed/generic model names, duplicate array entries, duplicate FAQ questions, empty FAQ answers, out-of-range `founded` years, duplicate description vs history, suspicious superlative claims, ECU-specific claims flagged for manual review.
5. **Merged-candidate validation** — schema + quality on the final brand object before it may be written.

Invalid AI output never enters `src/data` — it is recorded as a failed record.

## Promotion (publishing generated content)

```bash
npm run promote:brands                    # validate + preview (no writes)
npm run promote:brands -- --apply         # write accepted records into src/data/<slug>/brand.json
npm run promote:brands -- --allow-mock    # DANGEROUS — promotes synthetic mock test data
npm run promote:brands -- --allow-core-changes  # DANGEROUS — may overwrite verified core fields
```

Promotion refuses to:

- promote any record whose status is not `ok`;
- promote **mock** records unless `--allow-mock` is passed;
- overwrite core verified fields (`name`, `slug`, `description`, `logo`,
  production/discontinued counts) unless `--allow-core-changes` is passed;
- accept records failing schema/quality or whose slug does not match the directory.

Always review `brands.generated.json` manually before promotion.

## Failure / retry behavior

- Failed AI requests (network error, HTTP error, unparseable output) are
  retried with exponential backoff (`1s, 2s, 4s...`), up to `--retries`
  attempts.
- A single failing manufacturer does not abort the batch — it is logged as
  `failed` and the next record is processed.
- Records that fail schema or quality validation are also logged as `failed`
  with the reason.
- Pipeline exits `1` only if zero records succeeded.

Log line example (`brands.generation.log.jsonl`):

```json
{"log":"brand","slug":"ac","status":"ok","provider":"mock","attempts":1,"retries":2,"fields":["history","country"],"warningsCount":0,"error":null,"timestamp":"2026-08-12T09:50:06Z"}
```

## Recommended workflow for full dataset generation

1. `npm run generate:brands -- --limit 3` → inspect `brands.generated.json` manually.
2. `npm run generate:brands -- --limit 10` → inspect again.
3. Review quality, then `npm run generate:brands` for all brands with `brand.json`.
4. `npm run validate:generated` then `npm run promote:brands -- --apply`.
5. Refresh `brands.generation.log.jsonl` review for warnings requiring manual review.

## Current status & limitations

- Tested end-to-end with the **mock provider** (3- and 10-brand batches) and
  against a fake DeepSeek endpoint (verify retry, parsing, log redaction).
- Real DeepSeek output has **not** been reviewed for factual quality — a live
  run with a real `DEEPSEEK_API_KEY` is required and every generated record
  should be reviewed before promotion.
- Quality checks are heuristic. They cannot fully prevent plausible
  fabrication; warnings (ECU-specific claims, superlatives) indicate manual
  review.
- The pipeline currently processes brands that already have a
  `src/data/<slug>/brand.json` folder (43). The remaining ~1,199 brands in
  `src/data/brands.json` need folders created before full expansion.
